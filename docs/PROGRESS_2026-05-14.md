# Shiyi Progress Assessment — 2026-05-14

- Assessor: Kana
- Scope: product progress, implementation state, milestone readiness

## 1. Executive assessment

Shiyi is no longer just a PRD or architecture sketch. It has a working early capture-to-export foundation and enough tests to start behaving like infrastructure.

The project is currently at the transition point between:

```text
foundation implementation -> contract hardening -> scaled source expansion
```

My assessment: proceed with source expansion planning now, but keep default built-in source additions behind the P2 readiness gate. We should not let the desire for more sources turn Shiyi into a brittle scraper collection. 很想多抓源没错，但底座塌了就什么都别谈了。

## 2. What is already solid

### Product boundary

The boundary is clear and correct:

```text
Shiyi = Capture + Normalize + Neutral Preprocess + Distribution
Consumers = Domain Enrichment + Ranking + Product Output
```

This means Shiyi can serve AI Weekly, Demand Radar, Briefly-style products, and future consumers without becoming one product's private ranking engine.

### Architecture

The repo has documented and implemented the right early abstractions:

- adapters behind ports;
- shared fetchers;
- `InternalItem` as adapter-to-core boundary;
- raw and normalized artifacts;
- SQLite event records;
- optional neutral preprocessing;
- export/read path for consumers.

### Implementation

Current implementation includes:

- OpenAI RSS adapter;
- Anthropic news adapter;
- HTTP/RSS/Sitemap fetchers;
- HTML-to-Markdown normalizer;
- filesystem artifact store;
- SQLite event record store;
- CLI capture/list/export;
- capture windows with inclusive `since` and exclusive `until`;
- replay safety through `idempotency_key`.

### Tests

The project now has contract-oriented tests and golden fixtures. P2 added important semantic-drift gates around:

- `InternalItem` validation;
- adapter fixtures;
- OpenAI RSS golden output;
- Anthropic dedupe/replay behavior;
- export safety against raw/source DTO leakage;
- boundary E2E export smoke.

## 3. What is not done yet

P2 is not fully done just because the first gates are green.

Remaining gaps:

- fetcher contract matrix still needs broader error/pagination/window coverage;
- every built-in source should have consistent fixture layout;
- pipeline-to-persistence tests should cover partial failures and status semantics more explicitly;
- export/read tests should fully lock ordering, half-open windows, source filters, and consumer-facing schema;
- source readiness gate should be treated as mandatory before adding many default built-ins;
- source registry/config is not yet ready, so adding many sources directly into CLI conditionals will become messy.

## 4. Strategic recommendation

### Keep P2 as the current milestone

Finish enough test-boundary breadth that adding sources becomes safe.

### Start P2.5 source research immediately

Parallel source research is fine:

- inspect candidate sources;
- choose feed/API/sitemap approach;
- draft fixtures;
- identify brittle/noisy sources early.

But production built-in additions should follow the readiness gate.

### Add sources in low-noise batches

First batch should be official AI company/provider sources. These increase AI Weekly coverage without dragging Shiyi into ranking or community aggregation.

Recommended first batch:

- Google DeepMind / Google AI / Gemini;
- Meta AI;
- Microsoft AI / Azure AI;
- Hugging Face Blog;
- optional Mistral/Cohere if feeds are stable.

Delay HN/GitHub Trending/arXiv/media until registry and downstream aggregation are clearer.

## 5. Milestone implication

The milestone plan has been updated in `docs/MILESTONES.md`:

1. P1 foundation is done.
2. P2 test boundary remains active.
3. P2.5 source expansion batch 1 is next.
4. P3 should introduce source registry and scalable adapter configuration.
5. P4 should strengthen consumer distribution and operational reliability.
6. P5 can handle higher-noise community/research/media sources.
